## 1. Introduction to Cybersecurity and Defensive Testing

### 1.1 What is Cybersecurity?

Cybersecurity is the practice of protecting computers, servers, mobile devices, electronic systems, networks, and data from malicious attacks. As our world becomes increasingly digital, cybersecurity has become one of the most critical fields in technology. 

Think of cybersecurity like securing a physical building:
- **Firewalls** are like security guards at the entrance
- **Encryption** is like putting documents in a locked safe
- **Multi-Factor Authentication (MFA)** is like requiring both a key and a PIN to enter a secure room
- **Endpoint Detection and Response (EDR)** is like having security cameras and motion sensors throughout the building

### 1.2 What is Defensive Testing?

Defensive testing, also known as penetration testing or ethical hacking, is the practice of systematically testing computer systems, networks, or applications to find security vulnerabilities that malicious hackers could exploit. 

**Key Principles of Defensive Testing:**
1. **Authorization:** All testing must be done with explicit, written permission from the system owners
2. **Methodology:** Testing follows established frameworks and standards
3. **Documentation:** All findings are documented and reported responsibly
4. **Remediation:** The goal is to improve security, not to cause damage

### 1.3 Why Study Adversarial Tactics?

To effectively defend a system, you must understand how attackers think and operate. This is known as the "attacker's perspective" or "red team thinking." By understanding how attacks work, security professionals can:

- Identify vulnerabilities before malicious actors exploit them
- Implement proper monitoring and detection capabilities
- Develop effective incident response procedures
- Build stronger security architectures

**Important Distinction:** Studying attack techniques for defensive purposes is fundamentally different from malicious hacking. The key differences are:
- **Intent:** Defensive testing aims to improve security; malicious hacking aims to cause harm or gain unauthorized access
- **Authorization:** Defensive testing is performed with explicit permission; malicious hacking is done without permission
- **Disclosure:** Defensive testers report vulnerabilities to fix them; malicious hackers exploit or sell vulnerabilities

## 2. Understanding Active Directory (AD)

### 2.1 What is Active Directory?

Active Directory (AD) is a Microsoft Windows directory service that stores information about objects on a network and makes this information available to users and administrators. Think of it as a digital phonebook and security system combined.

**Key Components of Active Directory:**

1. **Domain:** A logical group of network objects (users, computers, printers) that share a common directory database. Examples: `company.local`, `sales.company.local`

2. **Domain Controller (DC):** A server that responds to security authentication requests (logging in, checking permissions, etc.) within a domain. Domain controllers are the heart of Active Directory.

3. **Users:** Individual accounts for people who need access to the network. Each user has a username, password, and set of permissions.

4. **Computers:** Devices that are "domain-joined," meaning they are registered with and managed by the Active Directory domain.

5. **Groups:** Collections of users or computers that share common characteristics. Groups are used to simplify permission management.

6. **Organizational Units (OUs):** Containers within a domain used to organize objects (users, computers, groups) hierarchically. OUs allow for delegated administration and Group Policy application.

### 2.2 How Authentication Works in Active Directory

When a user logs into a domain-joined computer, the following process occurs:

1. **Credential Entry:** The user enters their username and password
2. **Hash Creation:** The password is converted into a mathematical representation called a "hash"
3. **Kerberos Request:** The computer sends an authentication request to the Domain Controller using the Kerberos protocol
4. **Ticket Granting Ticket (TGT):** If the credentials are valid, the Domain Controller issues a TGT
5. **Service Tickets:** The user can then use the TGT to request service tickets for specific resources (file shares, printers, applications)

**Protocols Used in Active Directory:**

- **Kerberos:** The primary authentication protocol used in modern Active Directory environments. It uses "tickets" to allow nodes to prove their identity over a non-secure network.
- **NTLM (NT Lan Manager):** An older authentication protocol that is still supported for backward compatibility. It is less secure than Kerberos and should be disabled where possible.
- **LDAP (Lightweight Directory Access Protocol):** The protocol used to access and maintain distributed directory information services over an IP network.

### 2.3 Why Active Directory is a Target

Active Directory is often called the "crown jewel" of corporate networks because:

1. **Centralized Control:** AD controls access to most resources in a Windows network
2. **High Privileges:** Domain Administrators have control over all domain-joined computers and users
3. **Trust Relationships:** Compromising one domain can lead to compromise of trusted domains
4. **Persistence:** Attackers can maintain long-term access through AD credentials

## 3. Authorized Testing Frameworks & Standards

### 3.1 Why Use Frameworks?

Security testing frameworks provide structured methodologies that ensure testing is thorough, consistent, and comprehensive. They help security professionals:

- Avoid missing critical test areas
- Communicate effectively with clients and stakeholders
- Produce standardized reports
- Ensure legal and ethical compliance

### 3.2 PTES (Penetration Testing Execution Standard)

PTES is a comprehensive standard for penetration testing that defines seven phases:

#### Phase 1: Pre-engagement Interactions
This phase involves establishing the rules of engagement, including:
- Scope of the testing (what systems can be tested)
- Testing methods allowed or prohibited
- Timing and duration of testing
- Points of contact and escalation procedures
- Legal authorization and documentation

#### Phase 2: Intelligence Gathering
Also known as "reconnaissance," this phase involves collecting information about the target:
- **Passive Reconnaissance:** Gathering information without directly interacting with the target (e.g., searching public records, social media, WHOIS data)
- **Active Reconnaissance:** Directly interacting with the target to gather information (e.g., port scanning, DNS enumeration)

#### Phase 3: Threat Modeling
This phase involves identifying potential threats and vulnerabilities:
- What are the valuable assets?
- Who are the potential attackers?
- What are the attack vectors?
- What are the potential impacts?

#### Phase 4: Vulnerability Analysis
This phase involves identifying and validating vulnerabilities:
- Automated scanning using security tools
- Manual verification of findings
- Prioritization based on risk and impact

#### Phase 5: Exploitation
This phase involves attempting to exploit identified vulnerabilities:
- Gaining initial access
- Escalating privileges
- Maintaining access
- Achieving the testing objectives

#### Phase 6: Post-Exploitation
This phase involves determining the impact of the compromise:
- What sensitive data was accessible?
- What systems could be reached?
- What privileges were obtained?

#### Phase 7: Reporting
This phase involves documenting the findings:
- Executive summary for management
- Technical details for IT staff
- Remediation recommendations
- Risk ratings and prioritization

### 3.3 MITRE ATT&CK Framework

The MITRE ATT&CK (Adversarial Tactics, Techniques, and Common Knowledge) framework is a globally accessible knowledge base of adversary tactics and techniques based on real-world observations.

**Key Components:**

1. **Tactics:** The "why" - what the attacker is trying to accomplish (e.g., Initial Access, Execution, Persistence, Privilege Escalation, Defense Evasion, Credential Access, Discovery, Lateral Movement, Collection, Command and Control, Exfiltration, Impact)

2. **Techniques:** The "how" - the methods used to achieve the tactical goal (e.g., Phishing, Valid Accounts, PowerScripts, Scheduled Task, Access Token Manipulation)

3. **Sub-techniques:** More specific variations of techniques

**Why MITRE ATT&CK is Important for Defenders:**

- Provides a common language for discussing security incidents
- Helps map security controls to specific attack techniques
- Enables gap analysis in defensive capabilities
- Supports threat hunting and incident response

## 4. Active Directory Security Assessment Methodology

### 4.1 Enumeration and Discovery (Defensive Understanding)

Enumeration is the process of extracting user names, machine names, network resources, shares, and services from a system. In Active Directory, enumeration is a critical first step for both attackers and defenders.

**Common Enumeration Tools and Commands:**

1. **netdom:** A command-line tool that performs various domain administration tasks
   - Example: `netdom query domain` lists domain controllers

2. **dsquery and dsget:** Command-line tools for querying and retrieving directory services information
   - Example: `dsquery user -name *` lists all users in the domain

3. **PowerShell ActiveDirectory module:** Provides cmdlets for managing Active Directory
   - Example: `Get-ADUser -Filter *` retrieves all users

**Defensive Understanding of Enumeration:**

As a defender, you should understand what information enumerators can gather:

- **User Accounts:** Names, descriptions, when accounts were created/modified
- **Computer Accounts:** Domain-joined computers, operating systems
- **Groups and Permissions:** Who has what privileges
- **Trust Relationships:** Between domains and forests
- **Service Accounts:** Accounts used by applications and services

### 4.2 Privilege Escalation Pathways

Privilege escalation is the act of exploiting a bug, design flaw, or configuration oversight in an operating system or software application to gain elevated access to resources that are normally protected from an application or user.

**Common AD Privilege Escalation Vectors:**

1. **Unconstrained Delegation:**
   - **What it is:** A configuration where a computer account can delegate any service ticket to any other service
   - **Why it's dangerous:** An attacker who compromises a delegated computer can impersonate any user to any service
   - **Defensive control:** Disable unconstrained delegation where not required; use constrained delegation instead

2. **Constrained Delegation:**
   - **What it is:** A configuration where a computer account can only delegate service tickets for specific services to specific computers
   - **Why it's dangerous:** If misconfigured, attackers can abuse it to impersonate users
   - **Defensive control:** Review and minimize delegated services; monitor for abnormal ticket requests

3. **Resource-Based Constrained Delegation (RBCD):**
   - **What it is:** A newer AD feature that allows computer accounts to specify which other accounts can authenticate to them
   - **Why it's dangerous:** Attackers can modify RBCD properties to gain unauthorized access
   - **Defensive control:** Monitor for changes to RBCD properties; limit write permissions on computer objects

4. **Group Policy Object (GPO) Abuse:**
   - **What it is:** GPOs are used to configure settings for users and computers in an AD environment
   - **Why it's dangerous:** Attackers with GPO edit permissions can execute code as users or computers
   - **Defensive control:** Limit GPO editing permissions to security administrators only

5. **LAPS (Local Administrator Password Solution) Misconfigurations:**
   - **What it is:** LAPS is a Microsoft tool that manages local administrator passwords on domain-joined computers
   - **Why it's dangerous:** If misconfigured, attackers can read local administrator passwords
   - **Defensive control:** Ensure LAPS is properly configured and that only authorized accounts can read passwords

**Defensive Detection Points:**

- **Security Event Logs:** Monitor for unusual logon patterns, privilege assignments, and account changes
- **Kerberos Ticket Monitoring:** Look for abnormal ticket requests or ticket grants
- **LDAP Query Monitoring:** Detect unusual directory searches or attribute queries
- **GPO Modification Tracking:** Alert on changes to group policy objects

### 4.3 Lateral Movement Techniques

Lateral movement is the process by which an attacker navigates through a network to reach their target. After gaining initial access, attackers rarely find their target immediately.

**Common Lateral Movement Techniques:**

1. **Pass-the-Hash (PtH):**
   - **What it is:** An attack technique where an attacker authenticates to a remote server using the NTLM hash of a user's password, rather than the plaintext password
   - **Why it's dangerous:** It allows authentication without knowing or cracking the password
   - **Defensive control:** Implement Credential Guard; monitor for unusual authentication patterns

2. **Pass-the-Ticket (PtT):**
   - **What it is:** An attack where an attacker steals and reuses a Kerberos ticket to authenticate to other services
   - **Why it's dangerous:** It allows authentication without credentials
   - **Defensive control:** Monitor for abnormal ticket usage; implement ticket validation

3. **WMI and PsExec Remote Execution:**
   - **What it is:** Using Windows Management Instrumentation (WMI) or PsExec to execute commands on remote systems
   - **Why it's dangerous:** It allows command execution without user interaction
   - **Defensive control:** Monitor for WMI and PsExec usage; restrict administrative shares

4. **WinRM and SMB-based Lateral Movement:**
   - **What it is:** Using Windows Remote Management (WinRM) or Server Message Block (SMB) for remote execution
   - **Why it's dangerous:** These are legitimate administrative tools that can be abused
   - **Defensive control:** Monitor WinRM and SMB traffic; implement network segmentation

**Defensive Controls:**

- **LAPS Implementation:** Ensure local administrator passwords are managed and rotated
- **Just-In-Time (JIT) and Just-Enough-Administration (JEA):** Limit administrative access to when and where it's needed
- **Credential Guard and LSA Protection:** Protect credentials from extraction
- **Network Segmentation and Micro-segmentation:** Limit lateral movement opportunities

## 5. AI Agent Capabilities in Security Testing

### 5.1 Defensive AI Applications

Artificial Intelligence and Machine Learning are transforming cybersecurity. Here's how AI is used defensively:

**Security Automation:**

1. **Log Analysis and Anomaly Detection:**
   - AI can process vast amounts of log data to identify patterns that indicate malicious activity
   - Machine learning models can establish "normal" behavior and flag deviations

2. **Threat Intelligence Correlation:**
   - AI can correlate internal security events with external threat intelligence feeds
   - This helps identify if internal systems are interacting with known malicious indicators

3. **Incident Response Playbooks:**
   - AI can help generate and execute response procedures based on the type of incident
   - This reduces response time and ensures consistent handling

4. **Vulnerability Prioritization:**
   - AI can assess vulnerabilities based on exploit availability, asset criticality, and threat intelligence
   - This helps security teams focus on the most critical issues first

**Security Assessment Support:**

1. **Policy and Configuration Review:**
   - AI can review security policies and configurations for compliance with standards
   - It can identify misconfigurations that could lead to vulnerabilities

2. **Compliance Mapping:**
   - AI can map security controls to regulatory requirements (NIST, CIS, ISO 27001)
   - This helps organizations demonstrate compliance

3. **Security Control Effectiveness Analysis:**
   - AI can assess whether security controls are working as intended
   - It can identify gaps in coverage or effectiveness

4. **Attack Surface Mapping:**
   - AI can help identify and catalog all accessible assets and services
   - This helps ensure all potential entry points are secured

### 5.2 Understanding Adversarial AI Use

As defenders adopt AI, attackers are also exploring AI capabilities. Understanding these potential uses helps defenders prepare:

**Potential Adversarial Applications:**

1. **Social Engineering and Phishing Campaign Optimization:**
   - Attackers could use AI to generate more convincing phishing emails
   - AI could help tailor attacks to specific individuals or organizations

2. **Vulnerability Research and Exploit Generation:**
   - AI could assist in identifying vulnerabilities in software
   - It could potentially help generate exploit code

3. **Evasion Technique Development:**
   - Attackers could use AI to develop techniques to evade detection
   - This could include malware that adapts to avoid analysis

4. **Log Manipulation and Evidence Tampering:**
   - Attackers could use AI to alter logs or create false evidence
   - This could complicate incident response and forensics

**Defensive Countermeasures:**

1. **AI-Powered Threat Detection:**
   - Use AI to detect AI-generated attacks or anomalies
   - Implement behavioral analytics that are difficult for attackers to evade

2. **Behavioral Analytics and UEBA:**
   - User and Entity Behavior Analytics (UEBA) use machine learning to establish baselines and detect anomalies
   - This can help identify compromised accounts or insider threats

3. **Automated Incident Response:**
   - Implement SOAR (Security Orchestration, Automation, and Response) platforms
   - Use AI to accelerate response to common attack patterns

4. **Adversary Simulation and Red Teaming:**
   - Use AI to simulate attacker behavior for testing purposes
   - Conduct red team exercises that include AI-assisted attacks
